01 / THE PROBLEM

A single score is not a complete account of a system update.

Two systems can look similar in an aggregate report and still respond differently to consequential questions. Without matched cases, repeated runs, and traceable evidence, that change is easy to overlook.

01

Look beneath the average.

See the individual responses that moved, even when an overall score looks acceptable.

02

Separate change from noise.

Repeat both versions. Distinguish a consistent transition from answers that vary on re-run.

03

Make the result auditable.

Connect findings to frozen inputs, run records, checksums, and a release gate that can fail.

02 / THE METHOD

From an update to a reviewable decision trail.

RIDI is model-agnostic. Use an answer key if available, or compare answer text and review the differences yourself.

01
≡

Hold the questions constant

Compare the current and proposed configurations on matched inputs, with optional evidence passages.

02

Repeat both versions

Capture repeated outputs to reveal run-to-run instability rather than assume determinism.

03

Review regressions, improvements, stable changes, and cases whose answers vary.

Check recorded scores and run evidence. Optionally enforce strict limits in continuous integration.

04 / RESEARCH WITH RESTRAINT

Designed for scrutiny, not unquestioned trust.

RIDI makes observed changes easier to inspect. It does not determine whether a medical, legal, or other high-stakes decision is safe; it cannot replace human review or prove causal harm.

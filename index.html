00 / WHY USE IT

The score can hold still while the answers move.

That is the risk. If you ship, evaluate, or review an update, an unchanged average is not evidence that the answers people receive stayed the same.

P

Practitioner

You are about to change a prompt, a model, or the passages a system retrieves. You need the cases that moved, and a gate that can stop the build, before users see the new answers.

E

Evaluator

A task score answers a different question. RIDI Check reports item-level transitions on the same case ids, next to how often each version disagrees with itself.

R

Reviewer

You need a record you can re-read: matched items, repeated runs, and a stated limit. A gate failure is an application of those labels. It is not clearance to deploy.

· WHAT IT ADDS

An item-level audit, not another aggregate score.

HELM, lm-evaluation-harness, and Inspect are built to configure, score, and log evaluations. Their usual reported unit is a task score. This repository has not run them on the same items and does not claim to outrank them. What ridi-check adds is a report of item-level transitions on matched items, set next to an execution floor from repeated runs, with an exact conditional test beside the rounded-rate comparison, and a release gate that can fail a build. The exact test is labelled implementation pending confirmation against the registered protocol. The gate does not certify the system.

· WHO IT IS FOR

Use it when the unit of harm is one answer.

Use it to compare two versions of one system on the same case ids. Do not use it to rank models on a public leaderboard, to clear a clinical system, or to decide that an answer is correct when you have no answer key. Without a key, a difference is a change, not a regression.

· FAQ

Short answers, with the limits left in.

Does a model judge the answers?

No. Scoring is exact match after normalisation, or a function you supply. A judge would add its own error.

Is the exact test the registered bootstrap?

No. The registered analysis is a paired bootstrap with a 2-point margin. The package reports an exact conditional binomial test and labels it pending confirmation. The rounded-rate comparison is unchanged.

What if there is no answer key?

The report lists changes, not regressions. You judge which changes are worse. The release gate can count those judgments. It still does not certify the system.

× WHEN NOT TO USE IT

A gate failure is not clearance, and a pass is not either.

Do not use ridi-check as clinical clearance, as a ranking against HELM, Inspect, or lm-evaluation-harness, or as proof that a stable answer is a correct one. Two runs are a thin execution floor. The limitations page is the list, not a footnote.

01 / THE PROBLEM

A single score is not a complete account of a system update.

Two systems can look similar in an aggregate report and still respond differently to consequential questions. Without matched cases, repeated runs, and traceable evidence, that change is easy to overlook.

01

Look beneath the average.

See the individual responses that moved, even when an overall score looks acceptable.

02

Separate change from the execution floor.

Repeat both versions on the matched items. The execution floor is re-execution noise. A change that does not clear it is not evidence about the update.

03

Make the result auditable.

Connect findings to frozen inputs, run records, checksums, and a release gate that can fail.

02 / THE METHOD

From an update to a reviewable decision trail.

RIDI is model-agnostic. Use an answer key if available, or compare answer text and review the differences yourself.

04 / THE SCIENCE

Designed for scrutiny, not unquestioned trust.

RIDI compares matched items across repeated runs and sets the change next to an execution floor. The package reports that rounded comparison and, beside it, an exact conditional test labelled implementation pending confirmation against the registered protocol. Nothing here is clinical clearance.

Manuscript under review. Preprint forthcoming. Title: Identical relevance grades cannot certify retrieval-augmented AI answers.

Preregistered commercial replication: criterion H1c, support in at least 2 of 3 models after Holm, was not met. Gemini 3.8 Flash +0.0347 [0.0247, 0.0452] was supported. GPT-5.4 mini +0.0098 [-0.0024, 0.0221] and Claude Sonnet 5.5 +0.0074 [-0.0023, 0.0174] were not. The same differences were previously written here as percentage points: +3.47 points is +0.0347. The magnitude is model-dependent and has to be measured for each model.

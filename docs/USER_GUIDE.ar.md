# دليل استخدام ridi-check

لكل من يملك مساعداً ذكياً ويوشك أن يغيّره. لا تحتاج مجموعة اختبار ولا مفتاح إجابات ولا خلفية في
الإحصاء. النسخة الإنجليزية: [USER_GUIDE.md](USER_GUIDE.md).

## ماذا تفعل الأداة

بنيتَ مساعداً، وتوشك أن تغيّره: نموذج جديد، أو موجّه (prompt) جديد، أو وثائق مختلفة. تطرح
ridi-check الأسئلة نفسها على النسخة الحالية وعلى النسخة التي تريد إطلاقها، وتسأل كل نسخة أكثر من
مرة، ثم تريك:

- أي الإجابات **تغيّرت**؛
- أي التغيّرات **يثبت** عند إعادة سؤال كل نسخة، وأيها مجرد اختلاف المساعد مع نفسه؛
- وإن كانت عندك إجابات مرجعية: أي التغيّرات **تراجع** وأيها **تحسّن**.

لماذا يهم ذلك: قد يُبقي التحديث متوسط الدقة كما هو تقريباً بينما تنقلب إجابات كثيرة، لأن الإجابات
التي ساءت والتي تحسّنت يلغي بعضها بعضاً في المتوسط.

## جرّبها في دقيقة

```bash
pip install ridi-check
```

```bash
ridi-check demo --open
```

ينشئ هذا مجلداً باسم `ridi-demo` فيه مساعد تجريبي بنسختين، ثم يشغّل الفحص ويفتح التقرير. المثال لا
يحتاج شبكة ولا مفتاح API. يلزم Python 3.10 أو أحدث. وللنسخة التطويرية ثبّت من المستودع:
`pip install git+https://github.com/adeebnoor/ridi-check`.

## ثلاث طرق للاستخدام

| وضعك | ما تفعله |
|---|---|
| تستطيع أنت (أو مساعدك البرمجي الذكي) استدعاء المساعد من Python | `ridi-check init` ثم املأ دالة واحدة ثم `ridi-check run` |
| المساعد خدمة ويب أو برنامج سطر أوامر | `ridi-check run` مع عنوان `http://` أو `command:` (انظر دليل المطورين) |
| عندك الإجابات فقط، في جدول مثلاً | افتح [نسخة المتصفح](https://adeebnoor.github.io/ridi-check/) والصق الخلايا؛ لا تثبيت، وبياناتك تبقى داخل الصفحة. أو: `ridi-check init --by-hand` ثم املأ الجدول ثم `ridi-check report` |

## افحص مساعدك خطوة بخطوة

**1. أنشئ مجلد بداية**

```bash
ridi-check init my-check
```

يكتب أربعة ملفات: `questions.csv` و`my_assistant.py` و`ridi-check.json` و`ASK_YOUR_AI.md`.

**2. اكتب أسئلتك** في `questions.csv`: صف لكل سؤال مع `case_id` قصير وفريد. استخدم أسئلة يطرحها
مستخدموك فعلاً. من 30 إلى 100 سؤال بداية جيدة. إن كانت عندك إجابة مرجعية موثوقة لكل سؤال فأضف
عمود `expected`، وإلا فاتركه.

**3. اربط مساعدك.** افتح `my_assistant.py` واجعل `ask(question, version)` تستدعي مساعدك. قيمة
`version` هي `"current"` أو `"proposed"`؛ استخدمها لتبديل ما يغيّره التحديث فقط. وإن كنت تستخدم
مساعداً برمجياً ذكياً فالصق فيه محتوى `ASK_YOUR_AI.md` ودعه ينفّذ هذه الخطوة.

**4. جرّب خمسة أسئلة أولاً**

```bash
ridi-check run --limit 5
```

**5. شغّل الجميع**

```bash
ridi-check run
```

يُكتب التقرير في `ridi-out/report.html`. لا يضيع شيء إن توقف التشغيل: أعد الأمر نفسه فيكمل من حيث
توقف.

كم استدعاءً سيُجري؟ عدد الأسئلة × نسختان × عدد التشغيلات. خمسون سؤالاً بالتشغيلين الافتراضيين
تساوي 200 استدعاء لمساعدك.

## مع إجابات مرجعية أو بدونها

- **مع** عمود `expected` تُقيَّم كل إجابة صحيحة أو خاطئة (تطابق تام بعد تجاهل حالة الأحرف وعلامات
  الترقيم، أو بدالة تقييم من عندك). عندها يتحدث التقرير عن تراجعات وتحسّنات.
- **بدونه** يعرض التقرير الإجابات المختلفة. المختلف ليس بالضرورة أسوأ: تقرأ الإجابات المتغيّرة
  وتقول عن كل واحدة هل هي أسوأ أم أفضل أم بالمعنى نفسه.

## قراءة التقرير

**أين انتهت كل حالة.** ينتهي كل سؤال في مجموعة واحدة:

| المجموعة | المعنى | ما تفعله |
|---|---|---|
| تراجع ثابت | صحيحة قبل وخاطئة بعد، في كل تشغيل | اقرأها أولاً. كل واحدة إجابة محددة كسرها تحديثك. |
| تحسّن ثابت | خاطئة قبل وصحيحة بعد، في كل تشغيل | ما كسبته من التحديث. |
| تغيّر ثابت (بلا إجابات مرجعية) | إجابة مختلفة في كل تشغيل | اقرأ الإجابتين وأعطِ حكمك. |
| متقلبة عند الإعادة | نسخة أعطت نتيجة مختلفة عند سؤالها ثانية | ليست دليلاً على أثر التحديث. كثرتها تعني أن المساعد نفسه غير متسق. |
| خاطئة في النسختين | لم تتغيّر وما زالت خاطئة | التحديث لم يصلحها. تُعرض في قائمة مستقلة. |
| صحيحة في النسختين وتغيّرت الإجابة | مفتاح الإجابات يقبل الإجابتين والنص مختلف | لا تُحسب تغيّراً. بطاقتها تأتي بعد البقية؛ اقرأها إن كانت الصياغة مهمة، كرقم أو شرط. |
| صحيحة في النسختين / الإجابة نفسها | لم تتغيّر | لا شيء. |
| بلا إعادة تشغيل | شغّلت كل نسخة مرة واحدة | لا يمكن تأكيد شيء. شغّل مرتين. |
| لم تُقارَن | فشل استدعاء لمساعدك | أعد الأمر نفسه لإعادة المحاولة. |

**التغيّر بين النسختين مقابل تقلب إعادة التشغيل.** ثلاثة أشرطة: كم إجابة تختلف بين النسختين، وكم
إجابة تختلف عند سؤال النسخة *نفسها* مرتين. إن لم يكن الشريط الأول أطول من الآخرَين فالمجموع لا يخبرك
بالكثير: اقرأ الحالات الثابتة.

**حالات للمراجعة.** لكل حالة متغيّرة: السؤال، والإجابتان، وما أعطاه التشغيل الثاني، والمقاطع التي
استخدمتها نسخة واحدة فقط. المقاطع تُعرض ولا يُحكم عليها.

## الثبات لا يعني الصحة

النسخة التي تعطي الإجابة الخاطئة نفسها كل مرة تبدو ثابتة، وبلا إجابات مرجعية لا يستطيع التقرير أن يخبرك
بذلك. ثلاث طرق لتغطية هذا:

- أضف عمود `expected` للأسئلة التي يكون الخطأ فيها أشد ضرراً. عندها تُقيَّم تلك الحالات، وتُعرض الخاطئة في
  النسختين في قائمة مستقلة داخل التقرير.
- اقرأ بنفسك عيّنة من حالات «الإجابة نفسها» مرة واحدة قبل أن تعتمد على الفحص.
- أبقِ على أي تقييم صحة عندك. ridi-check تجيب عن سؤال آخر: ماذا غيّر هذا التحديث؟

## إعطاء حكمك (بلا إجابات مرجعية)

في التقرير أربعة أزرار عند كل تغيّر ثابت: أسوأ، أفضل، المعنى نفسه، غير متأكد. عند الانتهاء اضغط
**نزّل judgments.csv** وضع الملف بجانب `results.csv` ثم شغّل:

```bash
ridi-check report ridi-out/results.csv --judgments ridi-out/judgments.csv
```

## قبل الإطلاق

```bash
ridi-check gate ridi-out/results.csv
```

يطبع الأعداد وسطراً لكل حالة مخالفة، ويفشل (رمز الخروج 1) إذا وُجد تراجع ثابت، أو تغيّر ثابت لم
تحكم عليه بعد. يستطيع سكربت الإطلاق أن يتوقف عند ذلك. يمكنك السماح بعدد منها عبر
`--max-stable-regressions N`. البوابة تطبع أعداداً، والقرار يبقى لك.

الإجابات التي لم تثبت عند إعادة التشغيل لا تُحسب افتراضياً، لأن تباين إعادة التشغيل ليس تراجعاً. وحيث
تكون الإجابة الخاطئة مكلفة فاحسبها أيضاً: `ridi-check gate ridi-out/results.csv --max-unstable 0` يفشل
كذلك عند وجود أي حالة غير مستقرة، لأنها لم تتأكد صحتها ولم يتأكد خطؤها.

ومع مفتاح الإجابات قد تبقى الدرجة كما هي ونص الإجابة يقول شيئاً آخر؛ ومع تشغيل واحد لكل نسخة لا يتأكد
شيء، فالتغيّر الذي شوهد مرة واحدة يُذكر افتراضياً ولا يُحسب. وحيث تكون الإجابة الخاطئة مكلفة فأشدّ فحص هو:

```bash
ridi-check gate ridi-out/results.csv --strict
```

يجعل كل الحدود صفراً: التراجعات الثابتة، والتغيّرات التي لم تحكم عليها، والحالات التي لم تُقارَن، والحالات
غير المستقرة، والتغيّرات التي شوهدت في تشغيل واحد، ومع مفتاح الإجابات الإجابات التي تغيّرت ودرجتها ثابتة.
والحد الذي تعطيه بنفسك، مثل `--max-unstable 2`، يبقى كما أعطيته.

## نصائح عملية

- **شغّل كل نسخة مرتين على الأقل.** التشغيلان أقل ما يسمح بوصف شيء بأنه ثابت، وهما تقدير ضعيف.
  استخدم `--runs 3` أو أكثر حين يكون القرار مكلفاً.
- **غيّر شيئاً واحداً في كل مرة.** إن غيّر التحديث النموذج والموجّه معاً فالتقرير يريك ما تغيّر لا
  أيهما السبب.
- **غيّرت شيفرة مساعدك؟** استخدم مجلد مخرجات جديداً (`--out ridi-out-2`). الإجابات المسجّلة لا
  تُستبدل أبداً، فالمجلد القديم يحتفظ بالإجابات القديمة.
- **كل شيء تقريباً «متقلب» أو «متغيّر»؟** مساعدك يصوغ الإجابة نفسها بألفاظ مختلفة كل مرة. أضف
  إجابات `expected` مع دالة تقييم، أو اعتبر الإجابتين متطابقتين إذا اشتركتا في معظم الكلمات:
  `ridi-check report ridi-out/results.csv --similarity 0.9`.
  لا تستخدم تداخل الكلمات حيث تحسم كلمة واحدة، كجرعة أو حكم بنعم أو لا: قد يعدّ «مسموح» و«مسموح تحت
  الإشراف فقط» إجابة واحدة. التقرير يسمّي كل حالة يصنّفها بغير ما تصنّفها المطابقة التامة.
- **المفاتيح وكلمات السر** مكانها متغيرات البيئة، لا الملفات.

## عند حدوث مشكلة

| ما تراه | معناه | ما تفعله |
|---|---|---|
| `Stopped: the first calls all failed` | الاتصال بمساعدك لا يعمل بعد | اقرأ الخطأ المعروض وأصلح `my_assistant.py` ثم أعد التشغيل |
| `Stopped: 10 calls in a row failed because the service refused them` | حصة مستنفدة أو مفتاح ناقص أو حد للمعدّل: الباقي سيفشل بالطريقة نفسها | انتظر، أو أصلح المفتاح أو الخطة، ثم أعد الأمر نفسه؛ تُجرى الاستدعاءات الناقصة فقط |
| `N call(s) failed` | فشلت استدعاءات بعد 3 محاولات | أعد الأمر نفسه؛ تُعاد تلك فقط |
| `Nothing to call: every call is already recorded` | هذا المجلد فيه تشغيل مكتمل | استخدم مجلد `--out` جديداً إن تغيّر المساعد |
| `This output directory holds an earlier run with different inputs` | تغيّرت الأسئلة أو النسختان | استخدم مجلد `--out` جديداً |
| `Row 7: case_id ... appears more than once` | مشكلة في ملف CSV مع رقم الصف | أصلح ذلك الصف |
| `The file is not UTF-8 text` | برنامج الجداول حفظ الملف بترميز قديم | احفظه من جديد بصيغة «CSV UTF-8» (في Excel: ملف > حفظ باسم) |

كل رسائل رفض الملفات، وأكبر حجم جُرّب فعلاً، في
[المرجع](REFERENCE.md#input-files-what-is-read-and-what-is-refused).

## ما لا يخبرك به هذا الفحص

- يكشف التغيّر لا الصحة. النسخة التي تخطئ بالطريقة نفسها كل مرة تبدو ثابتة.
- الإجابة المتغيّرة ليست دائماً أسوأ. ومع الإجابات المرجعية، النتيجة بجودة تلك الإجابات.
- تشغيلان لكل نسخة تقدير ضعيف لمقدار تقلب المساعد من تلقاء نفسه.
- ليس شهادة سلامة، ولم يُختبر على الإيجنتات التي تستخدم أدوات أو تحتفظ بحالة.

تتبع ridi-check منهجية RIDI.
